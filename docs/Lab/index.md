# 靶场与实验

这一区收的是为了跑通某件事而存在的内容：平台怎么搭、环境怎么起、题目怎么解。跟其余分区的界线在于问的问题不同——别处回答「这个技术是什么」，这里回答「我怎么把它跑起来」。区内的界线同样具体：`02-Environment` 写 EVE-ng 怎么装，`04-Writeups` 写在这套拓扑上打通了什么。

## 收录范围

| 子目录 | 内容 |
|---|---|
| `01-CTF-Platforms` | CTF 竞赛平台部署（`CTFd`、`GZCTF`） |
| `02-Environment` | 网络仿真环境（`EVE-ng`），用于搭实验拓扑 |
| `03-CTF-Research` | CTF 方向的技术研究，按主题而不是按赛事组织 |
| `04-Writeups` | 靶机与赛题 writeup（如 `Docker-CFS`），复盘性质，不作为方法论文档 |

## 收录约定

实验记录与知识本体分开，这一条最容易被破坏——写着写着就把原理抄进了 writeup。原理留在攻防分区，`04-Writeups` 只记这台靶机上的实际顺序。

手法类内容也不放这里。CTF 技术本身与渗透技术是子集关系，手法属于对应的知识域分区，这一区只留「跑通了什么」。

其余的：

- 平台部署写可复现的最小步骤，配置文件与关键命令保留原文，平台本身的版本差异在页内显式标注。
- writeup 允许过期。题目与靶机版本会变，所以每篇开头记录环境与时间；过期不删除，只标注。
